# USB input and root storage

On x86_64, usb-server supports directly attached USB 1.x/2.0 HID Boot Protocol
keyboards/three-button mice and USB 2.0/3.x SCSI Bulk-Only Transport storage.
Composite interfaces are parsed independently. Limits are four controllers,
sixteen slots per controller and four HID interfaces per device.

## Run

```sh
USB_INPUT=on QEMU_HPET=on STORAGE_DEVICE=ahci make run
STORAGE_DEVICE=usb USB_INPUT=on QEMU_HPET=on make run
```

`USB_INPUT=off` remains the default and only controls emulated HID devices.
`STORAGE_DEVICE=usb` adds xHCI even when HID is off. Hardware controllers are
discovered independently of these QEMU options. The same complete Spencer image
contains firmware boot files and the Nanami GPT root partition.

Root discovery does not wait for input-service (which itself needs rootfs).
Boot-selected PCI/USB storage drivers report their root counts to Driver
Manager before publishing block-device. An initial empty USB scan keeps
watching storage connections; multiple roots or a failed probe fail closed.
Selection is by a unique Nanami GPT
partition, not proof of which disk firmware booted. Replugging a USB root never
retargets filesystem I/O to a replacement device.

USB probing is driven by storage attachment/detachment, not repeated on every
10 ms maintenance tick or block request. Port events received during a SCSI
probe are enumerated before submitting that inventory for selection. A manager
report of zero roots can be updated while no decision exists. A positive report
cannot be withdrawn; selection/ambiguity is final. Media arriving after a root
is selected cannot replace it. This is not a claim that all devices which might
appear later have been inventoried before selection.

Alpha now uses lazy range indexing for RAM and MMIO and a growing capability
hierarchy. Unused address gaps do not consume physical frame leaves. Both low
and firmware-assigned high BARs are supported; BAR addresses are not relocated.
See [physical capability management](../../nanami/src/nanami_core/memory/README.md).

## Boundaries and ownership

- Driver Manager serializes PCI discovery, BAR sizing/restoration and MSI/MSI-X
  disabling, and discloses resources only to selected driver PIDs.
- USB handles xHCI ownership handoff, controller reset, contexts, scratchpads,
  rings, root-port enumeration, control requests and interrupt/bulk endpoints.
  Supported Protocol capabilities identify USB2/USB3 speed classes. Empty
  protocol entries generated by QEMU with `p3=0` are ignored; they assign no ports.
  Capability headers and bodies are bounded by both the BAR and the next entry;
  forward links need no arbitrary entry-count limit. Unknown protocols reserve
  their port ranges but are not powered/reset/enumerated by this driver.
- HID reports use existing input queues and PS/2-set-1-style key codes. USB and
  PS/2 registrations coexist. Held keys/buttons are reference counted and
  released on detach/failure.
- BOT handles CBW/data/CSW, checked tags/residue, SCSI inquiry/readiness/capacity,
  READ/WRITE(10/16), bounded partition I/O and cache synchronization on writes.
  Storage requires 512-byte logical sectors, one BOT interface per device and
  up to 16 logical units. GPT probing is read-only.
- A bounded timer wait also polls the event ring; interrupt delivery is INTx
  when available. Debounce/reset/transfer delays use a separate notification
  from periodic polling and IRQs, so these events cannot finish a delay early.
  No raw hardware timer counter is exposed.
- Each endpoint has at most one transfer outstanding. HID completions remain
  serviced during synchronous block transfers, including on composite devices.
  Ring reuse follows completion or endpoint stop/reset. Fatal/timeouts retain
  DMA mappings; uncertain writes are not replayed automatically.
- AHCI probe DMA is quiesced before reusing buffers for another port.
  Driver failure paths retain DMA rather than exiting with a live controller.

Not implemented: external/integrated hubs, EHCI/OHCI/UHCI, UAS, non-512-byte
storage sectors, report-only/NKRO/vendor or SuperSpeed HID, wheels/extra buttons,
keyboard LEDs, suspend/resume, PCI hotplug, MSI/MSI-X delivery or AArch64 USB.
Attach test devices directly to xHCI root ports.

The user's updated xHCI 1.1 hardware log reaches USB rootfs and Honoka startup
with 34 scratchpads, 32-byte contexts and explicit USB2/USB3 PSI definitions.
Its USB3 table includes SSIC rates below 5 Gbit/s; this does not establish that
an SSIC device was attached. BIOS ownership was already clear, so ownership
handoff and 64-byte contexts remain unvalidated on hardware. A later desktop
hang is being investigated separately; successful enumeration is not a claim
of sustained hardware stability.

## xHCI initialization diagnostics

Initialization logs the capability registers, each extended-capability offset
and header, and each Supported Protocol/PSI definition. Malformed data reports
the offending BAR-relative offset, value (when readable) and reason. A timeout
reports BIOS ownership or operational register state separately from parsing.
Capture these lines together with Driver Manager's PCI BAR/resource log.

Explicit PSI definitions override default Speed IDs. USB3 classification does
not impose a 5 Gbit/s floor: xHCI 1.2b section 7.2.2.1 defines SSIC rates below
it, still using the USB3 wire protocol. This is parser support, not hardware
validation of SSIC attachment. PSIC=0 defaults follow USB 2.0/3.0/3.1/3.2
revision mappings; unknown revisions do not inherit invented defaults.

Unrecognized bit rates/link modes are logged and skipped per Speed ID, without
discarding supported siblings. Reserved zero IDs, duplicate IDs, incomplete
asymmetric Rx/Tx pairs, truncated capabilities and overlapping port ranges
remain errors. Ports with no usable protocol/speed table are not accessed. The
earlier real hardware log contained only `protocol`. The updated log includes
nonzero USB3 rates below 5 Gbit/s which the old parser rejected, and proceeds
through controller/storage initialization with the new parser.
The separate firmware-reserved RSDP/HPET mapping issue is not changed here.

## Tests

Host tests compile the production parsers, BOT wire handling, rings, PCI
preparation, storage-selection IPC, deferred root discovery and physical memory
manager. `usb-discovery` compiles the production storage lifecycle, SCSI/GPT
probe and manager arbitration with a fake bus and IPC. It covers an empty first
scan, late roots, topology changes during probing, ambiguity, controller failure,
no work on unchanged ticks, and no reselection after detaching a mounted root.
The memory
syscall mock checks ownership, alignment, watermarks and descriptor stability.

```sh
cargo test --release --manifest-path tests/native-performance/Cargo.toml -- --test-threads=1
RUSTFLAGS=-Zsanitizer=address cargo test \
  --manifest-path tests/native-performance/Cargo.toml --target aarch64-apple-darwin \
  --test usb --test usb-pci --test usb-storage --test usb-discovery --test physical-memory -- --test-threads=1
```

After building the image, use isolated QEMU snapshots:

```sh
python3 tests/usb/qemu-hid.py --image spencer/out/x86_64-pc99-release/spencer.img
python3 tests/usb/qemu-hid.py --image spencer/out/x86_64-pc99-release/spencer.img --usb-storage --usb2 --memory 8G --smp 1 --high-mmio
python3 tests/usb/qemu-hid.py --image spencer/out/x86_64-pc99-release/spencer.img --usb-storage --memory 32G --high-mmio --unplug-root
python3 tests/usb/qemu-hid.py --image spencer/out/x86_64-pc99-release/spencer.img --usb-storage --duplicate-root
python3 tests/usb/qemu-hid.py --image spencer/out/x86_64-pc99-release/spencer.img --usb-storage --empty-sata --high-mmio
python3 tests/usb/qemu-hid.py --image spencer/out/x86_64-pc99-release/spencer.img --virtio-storage --high-mmio
python3 tests/usb/qemu-hid.py --image spencer/out/x86_64-pc99-release/spencer.img --usb-storage --coexist-ps2 --hpet off --bash-smoke --no-network
python3 tests/usb/qemu-hid.py --image spencer/out/x86_64-pc99-release/spencer.img --usb-storage --late-root --coexist-ps2 --hpet off --bash-smoke --no-network
```

i8042 is disabled by default, so PS/2 cannot make USB tests pass. The harness
types commands, checks expected cursor movement, releases held Shift across
unplug/replug, and closes Shell using the replugged mouse. USB storage runs also
create a directory and require actual write traffic to the snapshot.
`--unplug-root` checks that a subsequent uncached read never reaches replacement
media. `--empty-sata` checks that unrelated media receives no probe writes.
`--coexist-ps2` additionally exercises PS/2 while USB is absent.
`--hpet off` exercises PIT selection. `--bash-smoke` replaces HTTP/hotplug with
interactive bash, three `busybox ls` children and exit, then checks mouse and
clock updates. Include bash and busybox (with the ls applet) in the rootfs.
`--no-network` omits the emulated NIC for this scenario. Timeout reports include
registers, interrupt controllers, USB and pointer selection.

`--late-root` boots firmware/kernel/initramfs from a private SATA clone with the
Nanami GPT entry removed (both GPT CRCs are updated). The original complete
image is attached through a USB snapshot only after USB startup and an empty
initial scan. It requires root publication exactly once, rootfs boot and USB
writes, and checks that the firmware-only SATA snapshot received no writes.
The pre-fix image enumerates the late USB disk but times out without publishing
block-device or vfs-service; host unit tests also cover the manager's previous
rejection of a zero-to-one root report.

The image is privately cloned/copied before launch. Writes affect snapshots
only. Logs/screenshots/firmware variables are kept in the printed temporary
directory. There is no real-device passthrough, LAN traffic or port forwarding.

### Validation (2026-09-16)

Deferred USB root discovery (after the notification fix):

- The pre-fix image reproduced the reported ordering: USB became online,
  enumerated the late storage device, then timed out without block-device or
  vfs-service. The same late-attachment test with the fixed image reached
  Honoka/Shell, wrote to USB rootfs, completed three bash child processes and
  exit, and kept the mouse and desktop clock updating (PIT, 4 CPUs, 4 GiB).
- Normal USB3 boot and root unplug/replug protection passed; the replacement
  disk received no rootfs reads. Duplicate USB/USB and AHCI/USB roots were
  rejected before block publication.
- All 190 release host tests passed (4 benchmarks ignored); the 9 discovery
  and 17 storage/selection tests also passed AddressSanitizer. The original
  manager failed the three new late-report regression cases before the fix.
- The x86_64 image was rebuilt. Kernel, Loader and register writeback are
  unchanged. These checks address the boot-time root wait, not proof that all
  intermittent post-desktop hangs on physical hardware have been resolved.

Deferred-notification SDK fix (after the capability-parser change):

- [SDK regression tests](../native-performance/ipc/README.md): the initial
  reproducer failed five cases before the fix. All ten current cases pass;
  the complete release host suite passes 177 cases (4 benchmarks ignored),
  and the ten IPC cases pass AddressSanitizer.
- USB3 root, PIT, 4 GiB / 4 CPUs, PS/2 present and no NIC: rootfs write, three
  interactive bash `busybox ls` fork/exec/wait cycles, bash exit, cursor movement
  and desktop clock advancement passed. An initial baseline probe used `true`,
  which this BusyBox build lacks; its status 127 was not a reproduced hang.
- AHCI root, HPET, 4 GiB / 4 CPUs, PS/2 present (`--stress 50`): HTTP launches
  before/after USB hotplug, cursor movement, mouse close, held-Shift release
  and PS/2 keyboard operation with USB removed all passed on the final image.
- All Rust apps/services, rootfs (with the user's extra Linux/FreeBSD binaries)
  and the x86_64 boot image were rebuilt. Kernel/Loader/Nun source is unchanged.
  The helper is inlined in timer-server's disassembly; the ordinary receive
  path reads the saved-notification word without exchanging it, and ordinary
  Reply-Receive remains one combined syscall.

This fixes a source-identified notification-loss path, not a confirmed
explanation for every previous timeout. Sustained real-hardware operation with
the updated SDK/rootfs still needs confirmation.

Current capability-parser change:

- Release host suite: 167 passed; 4 benchmark cases ignored. Includes 19 added
  capability/PSI tests for short/unknown entries, next-header overlap, long
  forward chains, custom/unsupported speeds, SSIC, defaults and asymmetric pairs.
- USB/PCI/BOT/physical memory AddressSanitizer suite: 61 passed.
- x86_64 USB server and complete image build passed.
- USB2 and USB3, each 8 GiB / 4 CPUs, high BAR: rootfs mount/write, USB keyboard HTTP launch
  before/after hotplug, cursor movement, held-Shift release on detach and
  replugged mouse close passed with PS/2 disabled.
- USB2, 8 GiB / 1 CPU, high BAR: rootfs mount, desktop and filesystem write
  passed. The HID test then timed out before HTTP launch: the screen retained
  only `http-ser` of the injected command. No capability/transfer error was
  logged; the cause is unconfirmed. This run is not a HID/hotplug pass.
- Follow-up AHCI-root tests with 4 GiB / 4 CPUs, low BAR and PS/2 enabled
  (`--coexist-ps2`, matching the launcher's input/storage settings): one run
  stalled at `http` during keyboard injection; two identical reruns and one
  `--stress 50` run passed cursor, click and hotplug checks. Tests used the
  user's rebuilt image, a headless display and isolated networking, not Cocoa
  or bridged networking. Guest source was unchanged between these runs.
  Successful reruns selected `QEMU HID Mouse`; the intermittent failure remains
  unconfirmed, not fixed. The harness now records pointer selection and includes
  PIC/Local APIC state in future timeout reports.

Earlier USB-storage/physical-memory change (before this parser change):

- x86_64 image build completed. AArch64 Rust applications and Nanami compiled;
  AArch64 image packaging stopped because the local Docker daemon needed to
  build U-Boot was unavailable. AArch64 USB runtime remains out of scope.
- USB2, 8 GiB / 1 CPU, default high BAR: rootfs mount/write, keyboard/mouse,
  held-Shift hotplug and mouse close passed.
- After delay-notification separation, USB2 with an unrelated SATA disk,
  8 GiB / 1 CPU and high BAR also passed the complete HID hotplug/write test;
  the unrelated SATA disk received no writes.
- USB3, 32 GiB / 4 CPUs, default high BAR: rootfs mount/write and unplug/replug
  protection passed.
- AHCI root with USB HID, 8 GiB / 4 CPUs, default high BAR: desktop, keyboard,
  cursor, held-Shift hotplug and replugged mouse close passed.
- Duplicate USB/USB and AHCI/USB roots were rejected before block publication.
- Virtio root with USB HID and a high BAR passed on a standalone rerun. Earlier
  concurrent runs timed out during virtio HID detach and USB/SATA HID replug;
  their cause was not established. The separate delay notification fixes a
  source-identified early-wake issue, not a proven explanation of both timeouts.

A9N and Loader source code is unchanged. The historical QEMU checks above do
not establish sustained physical-hardware stability.
